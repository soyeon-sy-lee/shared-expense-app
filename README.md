# 우리지출

카드 결제액과 정산 입금을 함께 살펴 **공동지출을 찾고, 실제로 내가 부담한 소비액을 계산하는 웹 애플리케이션**입니다.

**현재 상태:** 개인정보를 제거한 포트폴리오 데모 공개

**개발 방식:** 실제 거래를 직접 분류하며 규칙 기반(V1)과 학습 기반(V2) 방식을 비교·개선

> 공개 데모에는 실제 거래내역 대신 공동지출·승인필요·개인지출 대표 사례가 각각 5건씩 포함되어 있습니다. 실제 거래 데이터와 입금자 정보는 공개하지 않습니다.

## 프로젝트 소개

친구 4명의 식사비 10만원을 내 카드로 결제하고 나머지 3명에게 2만 5천원씩 돌려받았다면, 내 실제 소비는 2만 5천원입니다. 그러나 일반적인 자산관리 앱은 카드 결제액 10만원과 계좌 입금을 별개의 거래로 기록해 월 소비액을 실제보다 크게 보여주곤 합니다.

이 프로젝트는 이런 공동지출을 자동으로 찾아 정산 입금과 연결하고, 판단이 애매한 거래만 사용자가 확인하도록 만들었습니다. 같은 데이터에 두 가지 접근을 적용해, 사람이 만든 규칙과 사용자의 판정을 학습한 방식이 각각 어디에서 잘 작동하고 어디에서 한계를 보이는지도 비교했습니다.

| 항목 | 내용 |
| --- | --- |
| 해결하려는 문제 | 공동지출 때문에 카드 결제액이 개인 소비로 과대 계산되는 문제 |
| 주요 사용자 | 모임 비용을 먼저 결제하고 계좌이체로 정산받는 일이 잦은 사용자 |
| 제품 목표 | 반복적인 수동 조정은 줄이고, 애매한 거래에만 사람의 판단을 집중 |
| 비교 방식 | 생활 패턴을 반영한 규칙 기반 V1과 사용자 판정을 학습하는 V2 |

## 주요 기능

### 규칙 기반 V1

- 거래 종류와 금액을 바탕으로 `공동지출 확정`, `승인 필요`, `개인지출`로 분류합니다.
- 카페·음식점·배달 거래에는 서로 다른 금액 기준을 적용합니다.
- 쇼핑·의료비·통신비·대중교통비·교육비처럼 금액이 커도 개인지출인 항목을 먼저 제외합니다.
- 큰 지출 다음 날 들어온 소액 입금을 함께 살펴 공동지출 후보를 보완합니다.
- 정산받은 금액을 반영해 카드 결제액이 아닌 실질 소비액을 보여줍니다.

### 학습 기반 V2

- 거래를 한 건씩 보여주고 사용자가 공동지출 여부를 빠르게 판정할 수 있습니다.
- 음식점과 카페 거래를 우선 제시하고, 학습이 진행된 뒤에는 판단이 가장 애매한 거래부터 보여줍니다.
- 지금까지의 판정을 바탕으로 남은 거래의 공동지출 가능성을 계산합니다.
- 학습 결과와 승인 필요 거래, 공동지출 확정 건수를 한 화면에서 확인할 수 있습니다.
- 사용자의 판정에서 만들어진 의사결정나무를 자연어로 보여주고, 선택한 거래가 어떤 경로로 분류되는지 따라가 볼 수 있습니다.

### 월별 데이터 관리

- 로컬 환경에서 월별 카드·계좌 거래를 추가할 수 있습니다.
- 같은 거래가 여러 파일에 들어 있어도 중복을 제거합니다.
- 같은 달의 데이터를 다시 넣으면 기존 월 자료를 교체해 중복 누적을 방지합니다.
- 공개 데모에서는 개인정보 보호를 위해 파일 업로드와 영구 저장 기능을 제한합니다.

## 데이터와 검증

실제 카드·계좌 거래를 사용해 분류 흐름을 만들고, 사용자가 직접 판정한 거래를 기준으로 결과를 확인했습니다.

| 항목 | 결과 |
| --- | --- |
| 중복 제거 후 분석 거래 | 2,887건 |
| 직접 판정한 거래 | 335건 |
| 판정 구성 | 공동지출 52건 · 개인지출 283건 |
| 판정 소요 시간 | 초기 330건 기준 약 15분 |
| 공개 데모 데이터 | 공동지출·승인필요·개인지출 각 5건, 총 15건 |

### V1 검증 결과

| 확인 항목 | 결과 | 의미 |
| --- | --- | --- |
| 공동지출 발견률 | 94.2% (49/52) | 실제 공동지출 52건 중 49건을 확정 또는 승인 필요 거래로 찾음 |
| 후보 정확도 | 80.3% (49/61) | 공동지출 후보 61건 중 49건이 실제 공동지출이었음 |
| 자동 확정 정확도 | 93.8% (15/16) | 별도 승인 없이 확정한 16건 중 15건이 맞았음 |

V1은 공동지출을 놓치지 않는 데 강점이 있었고, 자동 확정 거래도 비교적 정확했습니다. 다만 승인 필요 거래에는 개인지출이 일부 포함되므로 최종 확인 과정은 여전히 필요합니다.

### V2 검증 결과

335건의 판정 데이터를 다섯 묶음으로 나누어 번갈아 검증했을 때 전체 정확도는 86.9%였습니다. 하지만 공동지출 발견률은 15.4%에 그쳤습니다. 공동지출이라고 예측한 건은 맞았지만, 전체 데이터에서 개인지출이 훨씬 많아 모델이 대부분의 거래를 개인지출로 판단한 결과입니다.

따라서 현재 V2의 높은 전체 정확도만으로 성능이 좋다고 해석할 수 없습니다. 이 프로젝트에서 더 중요한 지표는 실제 공동지출을 얼마나 놓치지 않는지이며, 현재 데이터에서는 V1이 V2보다 실용적인 결과를 보였습니다.

## 프로젝트 한계

- 한 사용자의 소비 패턴과 판정에 맞춰져 있어 다른 사용자의 생활 방식에 그대로 적용하기 어렵습니다.
- 직접 판정한 데이터는 음식점·카페와 애매한 거래를 우선 선택했기 때문에 전체 거래를 무작위로 뽑은 표본이 아닙니다. 위 검증 결과는 현재 데이터 안에서의 참고값입니다.
- 공동지출이 52건으로 적고 개인지출이 훨씬 많아 V2가 개인지출 쪽으로 치우쳐 있습니다. 더 많은 공동지출 사례와 균형 잡힌 학습 데이터가 필요합니다.
- 다음 날 입금이 있더라도 공동지출 정산이 아닐 수 있고, 정산이 여러 날 뒤에 들어오거나 여러 결제를 한 번에 정산하면 연결이 어려울 수 있습니다.
- 가맹점 이름이나 거래 분류가 부정확하면 규칙과 학습 결과도 함께 흔들릴 수 있습니다.
- 현재는 카드사·은행과 직접 연결하지 않으며, 실제 데이터 반영은 로컬 환경에서 파일로 진행합니다.

## 개인정보 보호

- 실제 거래내역, 계좌 입금 정보와 사용자 판정 데이터는 GitHub 및 공개 웹앱에 포함하지 않았습니다.
- 공개 데이터는 대표 사례 15건만 남기고 입금 메모를 익명화했습니다.
- 공개 웹앱에서 남긴 V2 판정은 현재 브라우저 세션에만 적용되며 서버에 저장되지 않습니다.
